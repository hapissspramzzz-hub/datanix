# Datanix — release status

**Implementation status: complete.** Datanix is a standalone PHP 8.3 / PDO / MySQL-MariaDB application; it is separate from EventHub and QUR’AN VISUAL.

## Acceptance outcomes

- Responsive Datanix public site, registration/login/profile, secure session handling, CSRF protection, rate limits and password-reset flow.
- Multi-workspace tenancy with workspace roles and server-side authorization; cross-workspace isolation was exercised in the test run.
- CSV, XLSX and JSON ingestion, attributed UCI Online Retail sample, paginated Explorer, export and private storage; SQL/API connectors are operator-configured and read-only.
- Natural-language chat with workspace-scoped deterministic calculations for supported metrics. Numeric answers, charts and provenance are generated by the query engine; the optional AI provider is limited to consent-gated qualitative narrative. Unsupported evidence returns the specified insufficient-data response.
- Free/Pro/Business limits, dashboard creation, saved insights, report generation and CSV/XLSX/print-to-PDF flows.
- Separate admin console, manual subscription review and confirmed-payment ledger. The app does not initiate charges or include a live payment gateway.
- Server-side secret handling, encrypted connector credentials, prepared statements, output escaping, protected routes and audit events.

## Verification record

- All PHP files passed `php -l` after the final analytics changes.
- A disposable end-to-end run passed **58 checks**, including authentication/CSRF, uploads, the 5,000-row UCI import, exact revenue calculation (110 for the test CSV), rejection of an unsupported profit metric, growth ranking, dashboard/report flows, XLSX package integrity, manual Pro activation and revenue ledger, and workspace isolation.
- After testing, Datanix was restored to a clean schema: **19 tables, 0 users, 0 datasets, 0 subscriptions and 0 payment records**. The UCI sample remains available for an authenticated user to import.
- The public HTTPS preview returned the route manifest and health response; session cookies were verified as `Secure`, `HttpOnly`, `SameSite=None`, with root path. Config, schema and environment-example paths were denied.
- A source scan found no unresolved TODO/FIXME/coming-soon or dummy-code markers in PHP, JavaScript, CSS or SQL files.

## Operator configuration (not application placeholders)

- Configure an HTTPS OpenAI-compatible endpoint and server-side key only if qualitative AI commentary is desired; deterministic analysis works without it.
- Configure a mail transport before relying on password-reset email delivery.
- Set the connector host allow-list and supply authorized read-only connection credentials before connecting external databases or APIs.
- Register an account and promote the intended first platform administrator using the SQL documented in `README.md`.
- Subscription requests and payment verification are deliberately manual. A payment ledger entry is not a charge.
